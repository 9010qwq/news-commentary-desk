# NewsDesk 0.2.0-rc2 · Windows 试用候选

解压整个 `NewsDesk-Windows-Portable.zip`，打开其中 `NewsDesk.exe`。请保留整个文件夹，不能只拷贝 exe。包内含 Python 运行组件和 Chromium，体积较大。下载后可用同页 `SHA256SUMS.txt` 核对文件。

这是单用户本地工具，没有注册/登录系统。初次启动不自动采集、不调用 API、不发送邮件。邮箱 SMTP、API 和定时开关都由使用者在本机填写；默认数据留在本机工具目录。不要公开自己的 data 文件夹、密码和 API Key。

## 此发布的自动检查

此预发布只会在 Windows 工作流全部通过后创建：
- 离线自动测试
- PyInstaller 打包
- 实际运行便携 EXE，并验证其自身的打包 Chromium 能启动空白页面
- 实际 EXE 的本机 HTTP 与中文界面连接、设置保存及重载
- 原生浏览器下载真实生成的空白 XLSX 和截图 ZIP，确认仍无新闻，周报显示35篇缺口
- 冻结EXE使用同包Chromium访问指定新京报原文，原页元数据及有效PNG检查必须通过，否则不发布
- 确认空白界面测试没有调用 API、发邮件或开启自动采集

在 [Windows运行#3](https://github.com/9010qwq/news-commentary-desk/actions/runs/37814615207) 中另有一次指定新京报公开原文的独立尝试，通过冻结EXE的正常抓取/解析/截图路径执行。该运行报告的 `public_source.status` 单独记录成功或站点/网络阻断；不绕过限制，也不在后续纯本机冒烟重跑时再次请求该文章。截图和正文只在临时目录使用并删除，公开产物仅保留元数据。这个单篇结果不能证明每天5篇、所有来源或周报投递全流程。

独立的空白界面截图和 JSON 冒烟报告位于对应 Actions 运行的 `NewsDesk-Windows-Smoke-Report` 产物中，不是新闻网页截图样本。

## rc2 修复与真实截图验收范围

rc1的实际故障是主页面返回200，但等待DOMContentLoaded时被超时资源拖住。rc2保留网站全部内容和原有安全检查，改为成功的主请求加真实可见的指定标题和正文，临截图前再核对一次。没有关闭robots、TLS、公开网络校验或绕过验证码。

修复在 [轻量Windows诊断#3](https://github.com/9010qwq/news-commentary-desk/actions/runs/37819533978) 通过：新京报指定原文的标题、陈广江署名及日期正确，生成1440×3667、1510959字节的原页PNG。该次是源码运行；本rc2发布还要求**冻结EXE+同包Chromium**再次通过同一原文的PNG验收，否则不会发布。新闻HTML、正文和原图不进入代码、公开产物或Release。

验收只覆盖这一篇原文的正常读取、元数据及截图结构，不声称人工逐字视觉复核，更不等于每天5篇、所有来源和真实邮件周报都已验收。旧rc1标签及资产保持不变。建议解压到新文件夹试用，不覆盖正在运行的旧版本。

## 仍需注意

这是候选版本，不等于所有日常流程已验收。尚未完成干净用户电脑安装、Windows 凭据管理器、多媒体来源每天5篇及历史补采完整流程、真实邮箱送达、真实付费 API、真实周四定时运行及 Microsoft Excel 原生排版检查。通用媒体链接可能不兼容，缺口和错误会如实显示。代码尚未做专业安全审计，二进制未进行商业代码签名。

电脑必须开机联网且程序保持运行，定时任务才有效；不自动添加开机启动。初次试用建议手动采一篇、检查原文和截图、导出，再自行开启自动任务。遇到 Windows 安全警告请检查来源并自行判断，不要关闭系统防护。

详情见仓库 README、`docs/TEST_REPORT.md`、`docs/SECURITY.md` 和 `docs/RELEASE_CHECKLIST.md`。新闻原文及截图版权仍属于各媒体，软件开源不授予新闻内容再发布权。
